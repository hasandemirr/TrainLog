## 2. Mimarın beş odağı — durum

### 1. CSV üretimi domain/app'te saf fonksiyon, testli

`app/csv.ts` → `buildCsv(state): string`. DOM/dosya/tarayıcı API'si yok; dosyaya
indirme adapters'ta. Sütun düzeni normatif sabit `CSV_HEADER`:

```
Hafta;Tarih;Gün;#;Hareket;Hedef Set;Hedef Tekrar;Hedef RIR;
S1 kg;S1 tkr;…;S5 kg;S5 tkr;Toplam Hacim;Gerçek RIR;Not
```

- Ayraç `;`, dosya başında BOM, satır sonu CRLF (Excel tr).
- Ondalık **virgül** (D22) — ayraç `;` olduğu için güvenli. Alan kaçışı: `;`, `"`,
  CR/LF içeren değer tırnaklanır, tırnak ikilenir.
- **5'ten çok set:** ilk 5'i yazılır, **Not** sütununa `+N set CSV'ye sığmadı` eklenir
  (kullanıcının notu korunur, ` · ` ile ayrılır). **Toplam Hacim TÜM setlerden** hesaplanır
  — kırpma sayıyı bozmaz (testli).
- **Hedef sütunları seansın SOMUT program sürümünden** gelir (D15) — koşu ortası
  düzenleme geçmiş satırların hedefini değiştirmiyor (testli, S5 kapı testinin CSV'deki karşılığı).
- **İkame edilmiş slotta hedef sütunları boş** (D47): program hedefi o harekete ait değil.
  *Karar noktası:* alternatif, slotun hedefini yine de yazmaktı; yanıltıcı bulduğum için
  boş bıraktım. Mimar aksini isterse tek satırlık değişiklik.
- Boş kayıt satır üretmez; satırlar seans (tarih#sıra) sonra slot sırasında.
- **CSV yedek SAYILMAZ:** `exportCsvNow` `markBackup` dispatch etmez → yedek yaşını
  sıfırlamaz (önizlemede doğrulandı). D28'in "yalnız dışa" kuralı: karşılık gelen bir
  parse fonksiyonu yok, kurtarma biçimi JSON'dur; Ayarlar'daki metin bunu söylüyor.
